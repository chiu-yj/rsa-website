研究方法 / 透明且可追溯的證據

科學可信度，
從 說清楚限制 開始。

RSA 的研究核心是把建築環境數據轉譯成可理解、可追溯、能支持前期決策的資訊，同時清楚保留模型的限制。

01 / 研究架構

從輸入，到驗證，
再到使用者理解。

01 / INPUT

確認輸入

定義基地、建物幾何、環境來源與分析假設。

02 / ANALYZE

產生證據

依不同分析主題，使用適用的方法與模型。

03 / VALIDATE

檢驗結果

和參考工具比對，紀錄差異、環境與測試條件。

04 / EVALUATE

評估理解

規劃使用者研究，檢視資訊是否改善理解與決策。

02 / 歷史版本驗證

每個數字，
都有版本脈絡。

以下資料來自 RSA r42、r44 歷史開發紀錄，不能直接作為最新版本或全系統通過驗證的證明。

r42 / 直接陰影 IoU
0.9795

與 Radiance 參考結果比較的歷史紀錄，包含 3/3 標記通過的案例。

r42 / 邊界距離
0.25 m

特定測試條件下的 Hausdorff 距離，歷史面積偏差約 −2.05%。

r44 / 回歸測試
321

該版本歷史紀錄中標記為 PASS 的測試。

資料來源：RSA 內部研發交接與早期版本紀錄。要形成可重現的正式驗證，仍須整理基準案例、執行環境、原始資料、測試腳本並於現行系統重跑。

03 / 技術環境

整合分析，
保留方法依據。

RSA 以 Python 與 Streamlit 為主要研究原型技術，探索建築量體、時間、位置與環境視覺化的整合。

研發文件曾參考 OpenStreetMap、台灣 NLSC、中央氣象署、ERA5、Open-Meteo 等資料來源；出現在文件中不代表所有 API 已上線或資料精度已驗證。

04 / 研究限制

可信的研究，
不超越證據說話。

01 / 日照

僅針對測試條件

先前的日影比對不能推論任何基地、日期及新版本皆符合相同精度。

02 / 風

探索性分析

風向視覺化不等於可驗證的 CFD 風速、壓力或行人風舒適結論。

03 / UTCI

輸入與模型依賴

人體熱舒適需要明確的氣象、輻射、幾何與模型前提，不能單憑截圖認定可信度。

當前定位RSA 用於住宅基地前期資訊探索、可解釋環境證據與決策研究，不取代 Radiance、CFD、EnergyPlus 或依法規要求的正式工程評估。
05 / 研發路線

先穩定，再驗證，
最後評估人的理解。

NOW / 整合

穩定核心系統

整理 2D／3D 狀態、資料來源、輸入一致性與主要分析功能。

NEXT / 驗證

重做可重現的比對

以明確的基準案例與誤差指標驗證方法，並公開其適用邊界。

FUTURE / 使用者

驗證轉譯成效

比較資訊呈現與 AI 解釋，是否讓人更了解分析內容與設計取捨。
